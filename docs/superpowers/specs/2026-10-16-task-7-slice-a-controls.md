A later qualification proposal must resolve actual identities and unknown capabilities again; Slice A creates no approved live target.

## Account observation and ordinary bootstrap

The pinned `GetAccountParams` supports `refreshToken`; metadata requests use exactly `false`. The response distinguishes ChatGPT, API key and Bedrock accounts. Only the minimum non-secret classification and compatibility result should survive projection. Do not preserve email/account IDs or spread the raw response into evidence. The separate `getAuthStatus` response includes a sensitive `authToken`, so it is not used as a shortcut. A compatible account observation is not a successful subscription model request or entitlement proof.

Later explicit bootstrap approval may include runtime-owned auth/policy retrieval, refresh, credential/cache persistence, state initialization/migration, identity and logs. Those ordinary trusted effects are distinct from optional integrations. Slice A records effect categories and bounds its own messages/time/output; it does not claim exact internal HTTP counts, side-effect-free startup or that the command sandbox encloses runtime authentication traffic.

## Evidence classification and stop

Slice A requires explicit reviewed per-action limits: at most 30,000 ms active time, 262,144 output bytes and 15,000 ms cleanup. These are conservative implementation limits for this slice, not a replacement for the future campaign's shared accounting. A larger allowance needs a reviewed implementation change; no caller silently receives one. The effective supervisor deadline is a lifetime ceiling as well as a creation cutoff; a later phase approval cannot extend it. Intent describes the requested task, while the actual dispatched specification must retain its separately bounded deadline and durable authorization identity.

The new tests use simulated responses and fake owned processes to exercise controller decisions. They can establish message ordering, refusal, privacy, ownership checks and drainage logic. They cannot establish live authentication, effective host policy, sandbox enforcement, integration inactivity or actual cleanup. The five blocker labels and all 32 catalog probes remain unchanged.

The current qualification CLI must continue refusing unqualified startup. Neither a controller admission record nor a simulated result may close a blocker or create a new live seal. Slice B runners/accounting and Slice C live proposal preparation remain outside this implementation slice.
