## Parser, typed configuration, and diagnostics

The source files most relevant to Tasks 2 and 3 are:

- [`config_override.rs`](../../../.superpowers/sdd/2026-10-16-task-7-completion-and-repair/source/codex-0.162.1/codex-rs/utils/cli/src/config_override.rs#L19) defines global repeated `-c/--config key=value`. It splits on the first `=`, parses the right side as TOML, falls back to a trimmed string if TOML parsing fails, and canonicalizes the legacy `use_legacy_landlock` key. Root overrides are prepended to subcommand overrides, so later subcommand values take precedence.
- [`config_toml.rs`](../../../.superpowers/sdd/2026-10-16-task-7-completion-and-repair/source/codex-0.162.1/codex-rs/config/src/config_toml.rs#L166) defines typed `ConfigToml` fields, including login method, profile map, notification vector, SQLite path, reasoning effort, and web-search mode. [`overrides.rs`](../../../.superpowers/sdd/2026-10-16-task-7-completion-and-repair/source/codex-0.162.1/codex-rs/config/src/overrides.rs#L16) applies CLI paths by literal `path.split('.')` after the CLI layer has preserved the raw key spelling; it does not parse or unquote TOML keypath segments. The generated schema's `deny_unknown_fields` annotations are not by themselves proof of runtime strict rejection; `strict_config.rs` and the CLI flag define that behavior.
- [`diagnostics.rs`](../../../.superpowers/sdd/2026-10-16-task-7-completion-and-repair/source/codex-0.162.1/codex-rs/config/src/diagnostics.rs#L36) wraps TOML errors as `ConfigLoadError` with file path, line, column, message, and an optional source error. Typed TOML validation uses `serde_path_to_error`; formatting can include the raw message and source line.
- [`strict_config.rs`](../../../.superpowers/sdd/2026-10-16-task-7-completion-and-repair/source/codex-0.162.1/codex-rs/config/src/strict_config.rs#L27) identifies fields ignored by normal typed deserialization and creates structured configuration errors. [`layer_io.rs`](../../../.superpowers/sdd/2026-10-16-task-7-completion-and-repair/source/codex-0.162.1/codex-rs/config/src/loader/layer_io.rs#L160) parses loaded TOML and wraps parse/strict-field errors.
- [`doctor.rs`](../../../.superpowers/sdd/2026-10-16-task-7-completion-and-repair/source/codex-0.162.1/codex-rs/cli/src/doctor.rs#L530) explicitly notes that errors can echo configuration values and reports only typed metadata for `ConfigLoadError` (file, line, column), not the error message. This is the safer source pattern for Task 2; arbitrary error text must not be treated as a trusted schema projection.
- [`main.rs`](../../../.superpowers/sdd/2026-10-16-task-7-completion-and-repair/source/codex-0.162.1/codex-rs/cli/src/main.rs#L1830) routes `features list` through `cloud_config::load_config` using the captured root overrides. App-server errors flow from `run_main_with_transport_options(...).await?`; [`in_process_bootstrap.rs`](../../../.superpowers/sdd/2026-10-16-task-7-completion-and-repair/source/codex-0.162.1/codex-rs/app-server/src/in_process_bootstrap.rs#L106) loads startup config and propagates errors. These source paths explain a config/bootstrap error path, but do not identify the cause of the historical 114-byte stderr.

The pinned `codex-rs/Cargo.lock` records `serde 1.0.228`; both `codex-config` and `codex-utils-cli` resolve `toml 0.9.11+spec-1.1.0`. Other TOML versions are also present for other workspace crates and should not be substituted for these consumers.

## Approved diagnostic input and compatibility findings

The exact approved argv remains in the read-only [prior proposal](../../../.superpowers/sdd/2026-10-16-task-7-blocker-resolution/diagnostic-correction-1/campaign/proposal.json). Its command is root-level repeated `-c` overrides followed by `features list`: Windows sandbox `mxc`; a named permissions profile plus its table; plugins/apps/hooks false; empty notify; web search disabled; OpenAI provider and ChatGPT login; model and reasoning effort; a SQLite home path; four MCP servers disabled. The proposal itself carries the exact values and paths; this inventory does not copy host configuration values or credentials.

Source comparison established one concrete approved-argv defect: `mcp_servers."bambu".enabled=false` is preserved as a raw key string, then `overrides.rs` splits on every literal dot. The segments are `mcp_servers`, `"bambu"` (including quote characters), and `enabled`; quotes are not parsed or removed. The override therefore does not target the intended `bambu` map entry. The same defect affects the four quoted simple-name MCP overrides in the approved argv. Use bare simple segments such as `mcp_servers.bambu.enabled=false`, or a correctly encoded whole-table override, and test key/merge precedence in Task 3. This finding does not establish the historical startup failure cause. Other inspected values (`mxc`, `chatgpt`, `ultra`, and named permission-profile structures) are represented in the pinned schema/types, but that is not full semantic validation of every nested permission policy or an effective-policy assertion. The historical diagnostic has 114 stderr bytes and no feature rows; its underlying error remains **UNKNOWN**.

The pinned CLI source confirms `codex app-server --strict-config --stdio`; `--stdio` is documented as equivalent to `--listen stdio://` and conflicts with `--listen` if both are supplied. App-server `--listen` documents `stdio://` (default), `unix://`, `unix://PATH`, `ws://IP:PORT`, and `off` ([`main.rs`](../../../.superpowers/sdd/2026-10-16-task-7-completion-and-repair/source/codex-0.162.1/codex-rs/cli/src/main.rs#L571)). Sandbox command structs define `--permission-profile NAME`/`-P` and `--include-managed-config`; the latter requires a permission profile ([`cli/src/lib.rs`](../../../.superpowers/sdd/2026-10-16-task-7-completion-and-repair/source/codex-0.162.1/codex-rs/cli/src/lib.rs#L51)). These sandbox flags are distinct from app-server transport flags.
