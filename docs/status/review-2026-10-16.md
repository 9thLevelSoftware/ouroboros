## Fix before live qualification (Tasks 7–8)

These would make live runs fail for reasons unrelated to the boundary being qualified.

- **P1. Rate-limit updates end the turn as a quota stop** (Codex, Likely). `src/providers/codex/adapter.ts:207-208`: any `account/rateLimits/updated` notification emits `quota_error` and stops the session. The pinned protocol describes it as a sparse rolling update, so it can arrive on healthy turns.
- **P2. Valid protocol items stop the session** (Codex, Likely). `adapter.ts:227-233`: item types outside a fixed list stop the session, including `contextCompaction`, `sleep`, `subAgentActivity`, `hookPrompt` and `functionCallOutput`. Every `error` notification also stops it, even with `willRetry:true`.
- **P3. Bash is denied after a `cd`** (Claude, Likely). `adapters/claude/src/session.ts:55`: the PreToolUse gate requires `request.cwd === projection.cwd`, so after `cd sub` every later Bash call is denied. This fails closed but blocks real work.
- **P4. Commands can't run builds or tests** (Codex, Traced). `adapter.ts:250-252`: approval policy `untrusted` plus deny-all means the worker can only run commands Codex already trusts.
- **P5. Quota/auth failure at `turn/start` is unclassified** (Codex, Traced). `transport.ts:85`, `adapter.ts:283`: it becomes generic `PROVIDER_DISPATCH_FAILED`, so the controller can't checkpoint `WAITING_FOR_QUOTA`.

## Store and contracts (block Tasks 9–14)

- **S1. No exit from a crash (Traced).** `src/store/database.ts:116`, `:69`. `claim` refuses while the repo is owned or has pending actions, and every action write needs the lost owner token. Nothing can mark actions `OUTCOME_UNKNOWN`, release the repo or start a new generation. `reconcileEvidence` (`:135`) only reports. Task 14 needs a fenced reconcile/takeover operation.
- **S2. Snapshots would be corrupted (Traced).** `src/store/artifacts.ts:80-84`: `publishArtifact` always applies the 10/100 MiB output caps and secret redaction. Snapshot/baseline bytes would be truncated or redacted, so Tasks 9–10 need a byte-exact publish path. Also:
  - `maxSnapshotBytes` is never enforced;
  - hashing reads whole files into memory (`database.ts:134`, `artifacts.ts:98`).
- **S3. No persistence for runs, checks or knowledge (Traced).**
  - There is no run-transition API (`phase`, `blocker`, refs, `repairCount`, budgets), which Task 13 needs.
  - `checks`, `proposals` and `knowledge_versions` have no RunStore methods.
  - There is no migration runner beyond version 1, so new tables are blocked.
- **S4. Control requests can be lost (Traced).** `database.ts:137`: they are consumed at most once, so a CANCEL is lost if the controller crashes before acting. Requests from generation N are also invisible to generation N+1.
- **S5. Redaction leak, low (Traced).** `artifacts.ts:23-33`: a secret that is a prefix of another, split across chunks, leaks the tail. Example: `['abc','abcdefXYZ']` over chunks `'abcde'`,`'fXYZ'` → `[REDACTED]defXYZ`.
- **S6. Write lock and fsync on every chunk (Traced).** Each output chunk takes an `IMMEDIATE` transaction plus fsync. Read-only APIs also take write locks, so a concurrent CLI enqueue can produce `STORE_BUSY` in the middle of a capture.

## Runtime and supervisor (block Tasks 12 and 14)

- **R1. No exit status (Traced).** `native/supervisor/src/main.rs:118`, `linux.rs:511`: neither helper records exit code or signal. Without them, `CommandDefinition.expectedExit` and the spec §8.4 classification can't be met.
- **R2. WSL ownership can be escaped without the evidence showing it (Traced).** WSL interop (`/mnt/c/...exe`) or `systemd-run --user` starts work outside the observed slice. `inspectWsl` doesn't check interop is disabled (`src/runtime/wsl.ts:40`). Task 8 must cover both.
- **R3. Windows helper can exit with no drain evidence (Traced).** `main.rs:89,92,99`: `try_send(...)?` on a full output queue exits the helper. Kill-on-close still cleans up, but TS reports outcome-unknown.
- **R4. Stop reasons are indistinguishable, and backpressure is fatal (Traced).** Queue-full, budget-exhausted and broken-pipe all become `io_or_output_limit`. Task 12's classification needs them separated.
- **R5. Evidence doesn't survive a controller crash (Traced).** Windows drain evidence only goes to stdout. The Linux `retrieve` mode has no TS caller. Task 14 has nothing to reconcile from.
- **R6. Commands found by search path, low.**
  - `.bat`/`.cmd` executables are accepted, and `CreateProcessW` runs them through cmd.exe (not reachable from current callers).
  - `wsl.exe`/`codex` are resolved by search path, not absolute path (`wsl.ts:23`, `doctor.ts:81,95`).

## Qualification and CLI

- **Q1. The ledger is Codex/Windows only (Traced).** The target schema, probe registry and argument parser are hard-wired to codex/windows/win32. Generalise them before Task 8. None of Task 8's files exist.
- **Q2. Task 7 live probes are missing (Traced).** Worker orchestration, network endpoints, link/broker drivers, cancellation probes and auth/quota fault injection are all still to do.
- **Q3. `os.release()` misses Windows and MXC updates (Traced).** A sandbox update keeps the old receipt. The receipt is also bound to `src` sources, not the built `dist`.
- **Q4. Doctor is disconnected from the ledger (Traced).** It reads a `qualification.json` nothing writes, and reports `UNQUALIFIED` unconditionally.
- **Q5. Exit codes, low (Traced).** `doctor --qualify` exits 1 for both "unqualified" and "failed". Task 16 specifies 3/4.

## Tests and tooling

- **T1. Windows-only tests have no platform gate (Run).**
  - 6 files fail on Linux: 57 of 184 tests.
  - `qualification-verifier`/`task7-stage1` write hundreds of backslash-named fixture files into the repo root.
  - `npm run test:portable` excludes them, and Windows CI runs them.
- **T2. Tautological or weak tests (Traced).**
  - `turn_complete_is_not_ready` never passes the run object to the adapter.
  - `resume_does_not_restore_files` checks a property nothing sets.
  - `never_invokes_shell_with_unquoted_user_text` compares an argv literal.
  - The store crash tests only assert `ok === false`; every mode fails with `RUN_OWNED`, so the `RECOVERY_REQUIRED` branch is never exercised.
  - `capped_partial_secret…` greps `store.sqlite` but not the WAL file.
- **T3. Tests aren't type-checked (Run).** Vitest strips types and the root tsconfig only includes `src/**`, so type errors in tests are invisible.
- **T4. Adapter advisory, low (Run).** `node-forge` (high-severity advisory, signature verification) arrives through `@anthropic-ai/sandbox-runtime@0.0.79`. It is not on a code path Ouroboros uses directly. Revisit when sandbox-runtime is next re-pinned.
